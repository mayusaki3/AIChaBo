# 認証・秘密ストア テスト仕様

本書は、  
spec「認証・秘密ストア仕様（doc-20260120-033500Z-RS4K）」に定義された  
**不変条件・堅牢性要件・例外ポリシー**が、実装において満たされていることを  
テストにより検証するための testspec である。

---

## COMMON-SECRET-T01-01 encrypt / decrypt / roundtrip / LWW
<!-- hldocs:sec_id=cs-t01-01 -->

### 概要

SecretStore に保存された認証情報が、

- 暗号化・復号を経て正しく取得できること
- 並列更新時に LWW（Last Write Wins）が成立すること

を検証する。

### 前提条件

- SecretStore が初期化済みである
- 有効な master key が利用可能である

### 検証内容

- ユーザー単位の認証情報を put した後、get で同一内容が取得できる
- サーバー単位の認証情報を put した後、get で同一内容が取得できる
- 同一キーに対する並列 put の結果が決定的である

### 期待結果

- 復号に成功した値のみが「存在する鍵」として扱われる
- 並列更新後の最終状態は一意に定まる

  - doc-20260120-033500Z-RS4K#並列更新（LWW）

## COMMON-SECRET-T01-02 edge / guard / compatibility
<!-- hldocs:sec_id=cs-t01-02 -->

### 概要

入力値異常、旧形式データ、永続化データ破損時においても、  
処理が停止せず安全側に継続されることを検証する。

### 前提条件

- SecretStore が初期化済みである

### 検証内容

- provider が空の場合に ValueError 等で明示的に拒否される
- 旧形式（prefix 差異等）のデータが互換的に読み取れる
- JSON 破損時に空構造として復旧される
- delete 操作が例外を投げずに完了する

### 期待結果

- 仕様で定義された安全側挙動が維持される
- 処理が途中で中断されない

- 認証・秘密ストア仕様  
  - doc-20260120-033500Z-RS4K#自己修復要件  
  - doc-20260120-033500Z-RS4K#削除操作の堅牢性  
  - doc-20260120-033500Z-RS4K#エラーおよび例外ポリシー

## COMMON-SECRET-T01-03 init / recovery
<!-- hldocs:sec_id=cs-t01-03 -->

### 概要

SecretStore の初期化および復旧処理が、  
主要な運用シナリオにおいて正しく機能することを検証する。

### 前提条件

- 永続化領域が存在する、または未作成の状態である

### 検証内容

- master key が存在しない場合に新規生成される
- 既存 master key が存在する場合はそれを優先して使用する
- 破損した永続化データが読み飛ばされる
- 一時ファイルが残存しない

### 期待結果

- 初期化および復旧処理が例外なく完了する

- 認証・秘密ストア仕様  
  - doc-20260120-033500Z-RS4K#SecretStore仕様  
  - doc-20260120-033500Z-RS4K#自己修復要件

## COMMON-SECRET-T01-04 delete robustness
<!-- hldocs:sec_id=cs-t01-04 -->

### 概要

削除系 API が、存在しないデータや部分破損状態に対しても  
堅牢に動作することを検証する。

### 前提条件

- SecretStore が初期化済みである

### 検証内容

- get_user_keys において破損トークンがスキップされる
- get_server_keys において server_id 不在時も安全に処理される
- delete 操作が空・欠落状態でも失敗しない

### 期待結果

- delete 系操作が True / False の戻り値のみを返す
- 例外が呼び出し元へ伝播しない
