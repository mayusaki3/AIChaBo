# 認証・秘密ストア_テスト仕様

## 1. 目的

認証情報（LLM APIキー等）の管理が、以下を満たすことを確認する。

- ユーザー単位（UserSessionManager / SecretStore）での登録・参照が正しい
- サーバー共有（ServerSessionManager / SecretStore）での登録・参照が正しい
- 秘密ストア（暗号化・復号、破損復旧、削除の堅牢性）が正しい

## 2. テスト対象（モジュール）

| 機能 | モジュール |
|---|---|
| 認証解決 | `common/chat/auth.py` |
| 認証共有 | `common/session/server_session_manager.py` |
| 秘密ストア | `common/secret/store.py` |

## 3. テスト実装ドキュメント

- tests 側の共通README（Index/実行方法/スイート対応）は **tests 配下の README** を参照すること  
  - [`tests/README_TEST_COMMON_SECRET.md`](../../../../tests/common/secret/README_TEST_COMMON_SECRET.md)

## 4. スイート構成（SecretStore）

### T01-01: encrypt/decrypt + roundtrip + LWW

- 仕様テスト：ユーザー鍵/サーバ鍵の put/get、並列 put の LWW を確認

### T01-02: edge / guard / compatibility

- 仕様テスト：provider 空、旧prefix互換、壊れJSON復旧（主要経路）、delete の安全性

### T01-03: init / recovery / tmp-cleanup（主要経路）

- 仕様テスト：master.key の生成/既存優先、破損トークンのスキップ、_save_json の tmp cleanup（主要経路）

### T01-04: delete robustness（全削除（指定ユーザー/指定サーバーの providers 全削除）/ 仕様テストとして固定）

- 仕様テスト：  
  - `get_user_keys` の「部分成功」（破損トークンはスキップ）  
  - `get_server_keys` の guild_id 不在  
  - `put_server_key` 上書き  
  - `delete_*` の空/欠落時の堅牢性

### T01-05: (impl) branch coverage（内部分岐の踏み増し）

- (impl) テスト：実装内部の分岐（例外枝、型不正復旧、cleanup 例外握り潰し等）を踏んでカバレッジを上げる  
- **仕様として維持すべき要件ではなく、実装品質（回帰検知/カバレッジ）のためのテスト** として扱う
