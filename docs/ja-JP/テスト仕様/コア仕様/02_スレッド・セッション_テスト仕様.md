## 3. 仕様テスト定義

### 3.1 サーバーセッションの生成と取得

#### 対応仕様
- [スレッド・セッション仕様 / 4. サーバーセッション（SSM）](../../仕様/コア仕様/02_スレッド・セッション仕様.md#4-サーバーセッションssm)

#### 観点
- server_id 単位で一意なセッションが生成される
- 既存セッションがある場合は再利用される
- 不正な server_id でも例外を送出しない

#### 該当テスト
- [COMMON-SESSION:T01-01-xx] server session lifecycle

---

### 3.2 ユーザーセッションの分離

#### 対応仕様
- [スレッド・セッション仕様 / 3. ユーザーセッション（USM）](../../仕様/コア仕様/02_スレッド・セッション仕様.md#3-ユーザーセッションusm)


#### 観点
- user_id ごとに独立した状態を持つ
- 他ユーザーの状態が混入しない
- user_id 未指定時は None として扱われる

#### 該当テスト
- [COMMON-SESSION:T02-01-xx] user session isolation

---

### 3.3 スレッド文脈の永続化

#### 対応仕様
- [スレッド・セッション仕様 / 5. スレッドコンテキスト（TCM）](../../仕様/コア仕様/02_スレッド・セッション仕様.md#5-スレッドコンテキストtcm)

#### 観点
- thread_id 単位で文脈が保持される
- Bot 再起動後も文脈情報が復元可能
- 削除済みスレッドは自動的に除外される

#### 該当テスト
- [COMMON-SESSION:T03-01-xx] thread context persistence
