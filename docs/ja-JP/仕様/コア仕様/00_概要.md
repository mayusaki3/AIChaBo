# AIChaBo コア仕様 概要

## Purpose（存在理由）

本書は、AIChaBo におけるコア機能の仕様上の定義を示す。

AIChaBo のコアは、UI 層および AI プロバイダ層から独立して、認証情報、会話文脈、チャット制御、共通ユーティリティを統合する中核制御層である。

本書は、AIChaBo コア仕様群における上位仕様として、後続の詳細仕様が従属する基準点を定義する。

---

## Non-goals（対象外）

本書は以下を対象外とする。

- Discord 等の UI 固有仕様
- OpenAI、Gemini、Claude 等の AI プロバイダ固有仕様
- 実装方法、クラス構成、アルゴリズムの詳細
- テスト条件、テストケース、検証手順
- 運用手順、移行手順、作業ガイド

---

## コアの定義

本仕様における「コア」とは、以下の条件をすべて満たす機能群を指す。

- UI 層に依存しない
- AI プロバイダ層に依存しない
- AIChaBo 全体で共通して利用される
- 状態管理、安全性、一貫性に責務を持つ
- 入力イベントから AI 応答までの中核制御を担う

コアは、入力、文脈、認証情報、ツール呼び出し、出力整形を統合し、AIChaBo として一貫したチャット処理を成立させる責務を持つ。

---

## レイヤ構造と責務境界

### 共通層（common）

共通層は、AIChaBo コアの中心として以下の責務を持つ。

- 認証情報および秘密情報を安全に管理する
- ユーザー、サーバー、スレッド単位の状態を管理する
- スレッド単位の会話文脈を管理する
- チャット実行ループを制御する
- UI 層および AI 層の差異を吸収する共通ユーティリティを提供する

共通層は、UI 固有実装および AI プロバイダ固有実装に直接依存してはならない。

### AI 層（ai）

AI 層は、AI プロバイダ固有の API 呼び出しを担う。

AI 層は、モデル指定、画像対応、画像生成、音声対応等のプロバイダ差異を内部で吸収する。

共通層から見た AI 層は、抽象化された provider 呼び出しとして扱われる。

### UI 層（ui）

UI 層は、Discord 等のプラットフォーム固有処理を担う。

UI 層は、共通層に対して入力イベント、出力メッセージ、添付、コマンド結果を受け渡す。

UI 層は、コアの内部状態および実装詳細に依存してはならない。

## コア機能仕様（上位要件）

### 認証情報管理

認証情報は、ユーザー単位設定とサーバー共有設定を区別して管理される。

認証情報の解決順は、ユーザー単位設定を優先し、ユーザー単位設定が使用できない場合にサーバー共有設定を参照する。

認証情報の存在判定は、保存値の文字列有無ではなく、復号可能であることを基準とする。

設定ファイル等の外部媒体は保存対象とせず、投入された内容のみが安全に保持される。

### 秘密ストアの堅牢性

秘密ストアは、永続化データの破損が検出された場合でも、コア処理全体を停止させてはならない。

不正構造または欠落ノードは、安全側の空構造へ正規化される。

削除操作は例外を外部へ送出せず、成否を表す値を返す。

### スレッド文脈管理

会話文脈はスレッド単位で管理される。

文脈の初期化、要約、再読み込みは、明示的な操作によって制御される。

Bot 再起動後も、スレッド管理状態は復元可能でなければならない。

削除済みスレッドに関する管理情報は、定義されたタイミングで整理される。

### チャット実行ループ

チャット実行ループは、入力から出力までの処理を、責務分離された順序で成立させる。

チャット実行ループは、少なくとも以下の責務を持つ。

- 入力の妥当性を確認する
- スレッド文脈を収集する
- 認証情報を解決する
- AI プロバイダを呼び出す
- 必要に応じてツール呼び出しを制御する
- 出力を整形し、必要な秘匿化を行う
- 処理結果をスレッド文脈へ反映する

継続応答およびツール呼び出しは、無限ループを防止する制約を持つ。

例外発生時は、ユーザー向けには簡潔なエラーを返し、詳細はログに記録される。

### Web 取得機能

Web 検索および Web 読み取りは、チャット処理に必要な共通機能として提供される。

URL 正規化、取得失敗時の扱い、本文抽出、取得結果の利用単位は、共通仕様として定義される。

危険 URL および禁止ドメインへの対応は、将来拡張可能な制約として扱われる。
