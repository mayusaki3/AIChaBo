# AIChaBo コア仕様 概要

## Purpose（存在理由）

本書は、AIChaBo における **コア機能の仕様上の定義**を示すものである。  
実装（旧コード・AI 生成コード）から独立した形で、コアが担う責務・境界・不変条件を明確化し、  
後続の詳細仕様および実装照合の基準点を提供する。

本書は「確認用」「チェックリスト用」の文書ではなく、  
**AIChaBo コア仕様における上位の正規仕様（canonical spec）**として扱う。

---

## Non-goals（対象外）

本書は以下を目的としない。

- UI（Discord 等）や特定 AI プロバイダの詳細仕様
- 実装方法、アルゴリズム、クラス構成の記述
- テスト条件、テストケース、検証手順の定義
- 運用手順、移行手順、作業ガイド

---

## コアの定義

本仕様における「コア」とは、以下の条件を満たす機能群を指す。

- UI 層および AI プロバイダ層に依存しない
- AIChaBo 全体で共通して利用される
- 状態管理・安全性・一貫性に責務を持つ

コアは、入力イベントを受け取り、文脈・認証・ツールを統合した上で  
AI 応答を生成・制御する **中核制御層**である。

---

## レイヤ構造と責務境界

### 共通層（common）

共通層は、以下の責務を持つ。

- 認証情報および秘密情報の安全な管理
- スレッド単位の状態および文脈管理
- チャット実行ループの制御
- UI 層・AI 層の差異を吸収する共通ユーティリティの提供

共通層は、UI 層および AI 層から **直接的な実装依存を持たれない**ことを前提とする。

### AI 層（ai）

AI 層は、以下を満たす。

- プロバイダ固有 API 呼び出しの実装を担う
- プロバイダ差異（モデル指定、画像対応等）を内部で吸収する
- 共通層からは「抽象化された provider 呼び出し」としてのみ利用される

### UI 層（ui）

UI 層は、以下を満たす。

- プラットフォーム固有の入力イベント・出力表現を扱う
- 共通層に対しては、入力・出力・添付・コマンド結果のみを受け渡す
- コアの内部状態や実装詳細に依存しない

---

## コア機能仕様（上位要件）

### 認証情報管理

- 認証情報は「ユーザー単位」および「サーバー共有単位」を区別して管理する
- 認証解決順は、ユーザー設定を優先し、次にサーバー共有を参照する
- 認証情報の存在判定は「復号可能であること」を基準とする
- 設定ファイル等の外部媒体は保存せず、内容のみを安全に保持する

### 秘密ストアの堅牢性

- 永続化データの破損が検出された場合でも、処理を停止してはならない
- 不正構造・欠落ノードは、安全側（空構造）へ自己修復される
- 削除操作は例外を投げず、成否を真偽値で返却する

### スレッド文脈管理

- 文脈はスレッド単位で管理される
- 文脈のクリア、要約、再読み込みは明示的な操作によって制御される
- Bot 再起動後も、スレッド管理状態は復元可能でなければならない
- 削除済みスレッドに関する情報は、定義されたタイミングで整理される

### チャット実行ループ

- 入力から出力までの処理は、定義された順序と責務分離に従う
- 認証解決、文脈収集、ツール起動は明示的な制御下で行われる
- 継続応答およびツール起動は、無限ループを防止する条件を持つ
- 例外時は、ユーザー向けには簡潔なエラーを返し、詳細はログに記録する

### Web 取得機能

- Web 検索および Web 読み取りは、共通層の機能として提供される
- URL 正規化、取得失敗時の扱いは仕様として定義される
- 危険 URL や禁止ドメインへの対応は、将来拡張可能な前提とする
