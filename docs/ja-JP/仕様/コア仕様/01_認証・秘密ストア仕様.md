# 認証・秘密ストア仕様

## Purpose（存在理由）

本書は、AIChaBo コアにおける **認証情報** および **秘密ストア（SecretStore）** の仕様を定義する。  
UI 層および AI 層から独立した形で、認証情報の解決規則、永続化、暗号化、堅牢性に関する  
**不変条件と責務境界**を明確化することを目的とする。

---

## Non-goals（対象外）

本書は以下を対象としない。

- UI 層（Discord 等）におけるコマンド仕様・操作手順
- 各 AI プロバイダ固有の API 仕様
- Web 取得機能に関する仕様
- 実装方法、クラス設計、アルゴリズム詳細

---

## 用語定義

- **認証テンプレート**  
  利用者が投入する JSON / JSONC 形式の設定情報。  
  chat / vision / imagegen の各用途別に構成される。

- **認証情報**  
  認証テンプレートから抽出され、内部で保持される provider / model / api_key 等の情報。

- **ユーザー設定**  
  特定ユーザーに紐づく認証情報。

- **サーバー共有**  
  ギルド（サーバー）単位で共有される認証情報。

- **SecretStore**  
  認証情報等を暗号化して永続化する仕組み。

- **自己修復**  
  永続化データの破損や不正構造が存在しても、処理を停止せず安全側に補正して継続する性質。

---

## 認証テンプレートの構造要件

### セクション構成

認証テンプレートは、以下の独立したセクションを持つ。

- chat：テキスト会話用
- vision：画像入力（説明・解析等）用
- imagegen：画像生成用

各セクションは、それぞれ独立した provider / model を持つことができる。

### 最低限の論理フィールド

- provider：利用する AI プロバイダ識別子
- api_key：プロバイダ API キー（機密情報）
- model：モデル名
- max_tokens：chat 用の任意指定
- その他拡張項目：任意（本仕様では制約しない）

---

## 認証情報の解決規則

### 解決順序（不変条件）

認証情報の解決順は、以下で固定する。

1. ユーザー設定
2. サーバー共有
3. いずれも存在しない場合は「未設定」

この順序は、すべてのチャット実行において一貫して適用される。

### 共有状態と削除の独立性

- ユーザー設定の削除は、サーバー共有状態に影響を与えない。
- サーバー共有の解除は、明示的な操作としてのみ行われる。
- 誤操作による共有解除を防止することを前提とする。

---

## SecretStore 仕様

### 目的

SecretStore は、以下を満たす。

- 機密情報を平文で保存しない
- 永続化データの破損時にも運用停止を引き起こさない
- 削除系操作を含め、例外による処理中断を発生させない

### 保存対象

SecretStore は、最低限以下を保存可能でなければならない。

- ユーザー単位の認証情報
- サーバー単位の認証情報

将来的な拡張は許容するが、本仕様では必須としない。

### 暗号化要件

- 保存される機密情報は暗号化されること
- 復号可能性が担保されていること
- master key の保持方法は運用に委ねるが、復号不能状態を常態化させてはならない

### 自己修復要件

以下の場合でも、処理を停止してはならない。

- 永続化データが JSON として破損している場合  
  → 空構造として復旧し、処理を継続する。

- 期待されるノードが dict でない場合  
  → 該当ノードを空 dict に再初期化し、処理を継続する。

### 鍵存在判定

- 鍵の存在判定は、文字列の有無ではなく **復号に成功するか** により行う。
- 復号に失敗した値は「存在しない」として扱う。

### 削除操作の堅牢性

- delete 系操作は例外を投げてはならない。
- 呼び出し側へは、以下の戻り値のみを返す。
  - 成功：True
  - 失敗：False

### 並列更新（LWW）

- 同一キーに対する並列更新が発生した場合、最終状態は決定的でなければならない。
- 本仕様では LWW（Last Write Wins）を採用する。
- tie-break の詳細は実装に委ねるが、結果が不定になってはならない。

---

## エラーおよび例外ポリシー

- コア層は、例外を UI 層へ伝播させない。
- 例外はログに記録し、呼び出し側には安全側の値を返却する。
- 開発者の明確な誤用（必須引数欠落等）は ValueError 等で表現してよい。

---

## セキュリティ要件

- api_key をログに出力してはならない。
- 永続化された情報は暗号化されていること。
- 共有認証の適用範囲と優先順位が明確であること。
