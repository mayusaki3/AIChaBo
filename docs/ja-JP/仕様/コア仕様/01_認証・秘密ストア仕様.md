# 認証・秘密ストア仕様

## Purpose（存在理由）

本書は、AIChaBo コアにおける認証情報および秘密ストアの仕様を定義する。

本書は、UI 層および AI 層から独立した形で、認証情報の構造、解決規則、永続化、暗号化、堅牢性に関する不変条件と責務境界を定義する。

---

## Non-goals（対象外）

本書は以下を対象外とする。

- Discord 等の UI 固有コマンド仕様
- 利用者向け操作手順
- 各 AI プロバイダ固有 API の仕様
- Web 取得機能の仕様
- 実装方法、クラス構成、アルゴリズムの詳細
- テスト条件、テストケース、検証手順

---

## 用語定義

### 認証テンプレート

認証テンプレートは、利用者が投入する認証設定情報である。

認証テンプレートは、用途別の AI 呼び出し設定を含むことができる。

### 認証情報

認証情報は、認証テンプレートから抽出され、AIChaBo 内部で保持される provider、model、api_key 等の情報である。

### ユーザー設定

ユーザー設定は、特定ユーザーに紐づく認証情報である。

### サーバー共有

サーバー共有は、ギルドまたはサーバー単位で共有される認証情報である。

### 秘密ストア

秘密ストアは、認証情報等の機密情報を暗号化して永続化する仕組みである。

### 自己修復

自己修復は、永続化データの破損または不正構造が存在する場合でも、処理を停止せず、安全側の状態へ正規化して継続可能にする性質である。

---

## 認証テンプレートの構造

認証テンプレートは、用途別の設定を独立して保持できる。

認証テンプレートは、少なくとも以下の用途区分を持つ。

- chat：テキスト会話用
- vision：画像入力、画像説明、画像解析用
- imagegen：画像生成用

各用途は、独立した provider および model を持つことができる。

認証テンプレートは、少なくとも以下の論理項目を表現できる。

- provider：利用する AI プロバイダ識別子
- api_key：プロバイダ API キーであり、機密情報として扱われる値
- model：利用するモデル名
- max_tokens：chat 用の任意指定トークン上限

上記以外の拡張項目は、認証情報の同一性および解決規則を破壊しない範囲で許容される。

---

## 認証情報の解決規則

認証情報の解決順序は、以下で固定する。

1. ユーザー設定
2. サーバー共有
3. 未設定

ユーザー設定が有効である場合、サーバー共有よりも常に優先される。

ユーザー設定が有効でない場合に限り、サーバー共有が参照される。

ユーザー設定およびサーバー共有のいずれも有効でない場合、認証情報は未設定として扱われる。

---

## ユーザー設定とサーバー共有の独立性

ユーザー設定の削除は、サーバー共有状態に影響を与えてはならない。

サーバー共有の解除は、ユーザー設定の削除とは独立した明示的な状態変更として扱われる。

サーバー共有状態は、ユーザー単位の認証情報操作によって暗黙的に解除されてはならない。

---

## 秘密ストアの責務

秘密ストアは、以下の責務を持つ。

- 機密情報を平文で永続化しない
- ユーザー単位の認証情報を保持する
- サーバー単位の認証情報を保持する
- 永続化データの破損時にもコア処理を継続可能にする
- 削除系操作を含め、通常運用上の不整合でコア処理全体を停止させない

秘密ストアは、将来的な保存対象の拡張を許容する。

保存対象の拡張は、既存の認証情報解決規則および暗号化要件を破壊してはならない。

---

## 暗号化要件

秘密ストアに保存される機密情報は、暗号化された状態で永続化される。

認証情報の存在判定は、保存値の文字列有無ではなく、復号可能であることを基準とする。

復号できない値は、有効な認証情報として扱われない。

復号不能状態が常態化している秘密情報は、認証解決に使用されない。

---

## 自己修復要件

秘密ストアは、永続化データが JSON として破損している場合でも、コア処理全体を停止させてはならない。

破損した永続化データは、安全側の空構造として扱われる。

期待されるノードが辞書構造でない場合、当該ノードは安全側の空構造として扱われる。

自己修復は、破損データを有効な認証情報として扱うことを意味しない。

---

## 削除操作の堅牢性

削除操作は、通常運用上の欠落または不整合を理由に例外を外部へ送出してはならない。

削除操作は、成否を表す結果を返す。

削除対象が存在しない場合、削除操作は安全側の失敗として扱われる。

---

## 並列更新規則

同一キーに対する並列更新が発生した場合、最終状態は決定的でなければならない。

AIChaBo の秘密ストアは、同一キーに対する競合解決規則として Last Write Wins を採用する。

Last Write Wins の適用結果は不定であってはならない。

---

## エラーおよび例外ポリシー

コア層は、秘密ストアの通常運用上の不整合を UI 層へ直接伝播させてはならない。

通常運用上の不整合はログ記録および安全側の戻り値によって扱われる。

開発者の明確な誤用は、通常運用上の不整合とは区別される。

---

## セキュリティ要件

api_key 等の機密情報はログへ出力されてはならない。

永続化された機密情報は暗号化されていなければならない。

共有認証の適用範囲および優先順位は、認証解決規則に従って一貫して扱われる。
