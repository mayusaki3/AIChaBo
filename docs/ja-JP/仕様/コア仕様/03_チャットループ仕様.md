# チャットループ仕様

本書は、AIChaBo コアにおける **チャット実行の中核処理（Chat Loop）** の仕様を定義する。  
入力受付から文脈処理、認証解決、LLM 呼び出し、ツール実行、出力確定までの一連の流れを  
**実装から独立した仕様**として整理する。

---

## 1. スコープ

対象：
- チャット実行の全体フロー
- Chat Core / Chat Loop の責務
- Continuation（継続応答）制御
- メッセージ構造（Message）
- テキスト分割（TextSplit）
- ツール（Web検索/読み取り等）起動の位置づけ

非対象：
- 各 LLM プロバイダ固有の API 仕様（AI層）
- Discord コマンドの受付処理（UI層）
- 認証情報の保存仕様（別：認証・秘密ストア仕様）
- セッション/文脈の保持仕様（別：スレッド・セッション仕様）

---

## 2. 基本概念

### 2.1 チャットループとは
チャットループとは、**1回のユーザー入力に対して行われる一連の処理**を指す。

- UI 層から「入力イベント」を受け取る
- 文脈・認証・ツールを考慮して LLM を呼び出す
- 出力を確定し、必要に応じて継続処理を行う

この一連は **再入可能・安全失敗可能**でなければならない。

---

## 3. 全体フロー（仕様）

1. 入力検証
2. 文脈収集（TCM）
3. 認証解決（ユーザー ＞ サーバー）
4. プロバイダ/モデル正規化
5. LLM 呼び出し
6. ツール起動（必要な場合）
7. 出力整形・確定
8. 文脈への反映
9. 継続判定（Continuation）

※ いずれかの段階で失敗しても、  
**UI層へ例外を伝播させず、簡潔なエラー応答で終了**する。

---

## 4. 入力検証

### 4.1 検証対象
- 入力が空でないこと
- 想定外の型でないこと
- UI層から渡される最低限のメタ情報が存在すること

### 4.2 失敗時の扱い
- ValueError 等で内部的に表現してよい
- UI層には「入力エラー」であることが分かる簡潔な文言を返す
- 文脈は変更しない

---

## 5. 文脈処理（TCM 連携）

- 現在のスレッドに対応する文脈を取得する
- /ac_newtopic 直後など、文脈が空の場合は空として扱う
- 文脈は **チャットループ内で直接永続化しない**
  - 反映は最終段階で行う

---

## 6. 認証解決と正規化

### 6.1 認証解決
- 認証解決は **チャットループ内で毎回行う**
- 解決順は以下で固定：
  1) ユーザー設定
  2) サーバー共有
- 解決できない場合：
  - LLM 呼び出しは行わない
  - UI層へ「認証未設定」相当のエラーを返す

### 6.2 プロバイダ/モデル正規化
- provider 名は内部表現に正規化する
- model 名が欠落/不正な場合：
  - デフォルトがあれば補正してよい
  - 補正不能な場合はエラーとして扱う

---

## 7. LLM 呼び出し

### 7.1 入力
- 現在の文脈
- 今回のユーザー入力
- 必要なシステムプロンプト/上書き設定
- 認証情報（provider/model/api_key）

### 7.2 出力
- テキスト応答
- ツール起動要求（ある場合）
- エラー（例外ではなく結果として）

---

## 8. ツール起動（Tool Call）

### 8.1 位置づけ
- ツール起動は **LLM の出力に基づく副処理**
- チャットループの一部だが、独立した責務を持つ

### 8.2 ガード条件
- 無限ループを防止する（最大回数等）
- 許可されていないツールは起動しない
- ツール失敗時：
  - ログに記録
  - チャット全体を失敗させない

---

## 9. 出力整形・確定

- LLM 出力およびツール結果を統合する
- redact などの安全処理を適用する
- UI 層へ返す最終テキストを確定する

---

## 10. 文脈への反映

- ユーザー入力と最終出力を文脈に追加する
- 途中失敗時は文脈を更新しない
- /ac_summary 実行時は、要約仕様に従う（別文書）

---

## 11. Continuation（継続応答）

### 11.1 概念
- 1回の応答で完結しない場合に、続けて LLM を呼び出す仕組み

### 11.2 開始条件（例）
- 出力トークン上限に達した
- 明示的な continuation 要求がある

### 11.3 終了条件
- 完全な応答が得られた
- 最大継続回数に達した
- エラーが発生した

### 11.4 失敗時
- 途中結果があればそれを返す
- 例外で停止しない

---

## 12. Message 構造（概念）

- role（system / user / assistant / tool）
- content（文字列 or 構造化データ）
- 付随情報（timestamp 等、任意）

※ Message は **文脈の最小単位**であり、  
UI 表示用構造とは一致しなくてよい。

---

## 13. TextSplit（テキスト分割）

### 13.1 目的
- 長文を LLM 制限内に収める
- 意味的な分断を最小化する

### 13.2 要件
- 文・段落単位を優先する
- 分割後も順序が保持される
- 分割不能な場合は安全側に倒す（切り捨て等）

---

## 14. エラー/例外ポリシー（本仕様範囲）

- チャットループは **決して UI 層を例外で停止させない**
- 例外はログに残す
- UI には以下のいずれかを返す：
  - 認証未設定
  - 一時的なエラー
  - 処理不能（入力不正 等）

---

## 15. 仕様-実装 照合ポイント（本書対応分）

- フロー順序が概ね一致しているか
- 認証解決が毎回行われているか
- ツール起動にガードがあるか
- 文脈反映が「成功時のみ」か
- Continuation が無限に回らないか
- 例外が UI 層に漏れていないか
