# チャットループ仕様

## Purpose（存在理由）

本書は、AIChaBo コアにおける **チャット実行の中核処理（Chat Loop）** の仕様を定義する。  
入力受付から文脈処理、認証解決、LLM 呼び出し、ツール実行、出力確定、継続制御までの一連の流れを、  
**実装から独立した宣言仕様**として明確化する。

---

## Non-goals（対象外）

本書は以下を対象としない。

- 各 LLM プロバイダ固有の API 仕様（AI 層）
- Discord 等 UI 層におけるコマンド受付・表示仕様
- 認証情報の保存・暗号化方式（別：認証・秘密ストア仕様）
- セッション／文脈の保持方式（別：スレッド・セッション仕様）

---

## 基本概念

### チャットループの定義

チャットループとは、**1 回のユーザー入力に対して実行される処理単位**である。  
本処理は以下の特性を満たす。

- 再入可能であること
- 途中失敗時にも安全に終了できること
- UI 層を例外で停止させないこと

---

## 全体フロー（不変順序）

チャットループは、以下の順序で処理される。

1. 入力検証  
2. 文脈収集（TCM）  
3. 認証解決（ユーザー ＞ サーバー）  
4. プロバイダ／モデル正規化  
5. LLM 呼び出し  
6. ツール起動（必要時）  
7. 出力整形・確定  
8. 文脈への反映  
9. 継続判定（Continuation）

いずれかの段階で失敗した場合でも、  
**UI 層へ例外を伝播させず、簡潔なエラー応答で終了**する。

---

## 入力検証

### 要件

- 入力が空でないこと
- 想定外の型でないこと
- 最低限のメタ情報が存在すること

### 失敗時の扱い

- 内部的には ValueError 等で表現してよい
- UI 層へは「入力エラー」と判別可能な簡潔な応答を返す
- 文脈は更新しない

---

## 文脈処理（TCM 連携）

- 現在のスレッドに対応する文脈を取得する
- 文脈が存在しない場合は空として扱う
- チャットループ中は文脈を直接永続化しない
- 文脈反映は最終段階でのみ行う

---

## 認証解決と正規化

### 認証解決

- 認証解決は **各チャットループごとに必ず実行**される
- 解決順序は以下で固定する。
  1. ユーザー設定
  2. サーバー共有
- 認証未解決の場合、LLM 呼び出しは行わない

### プロバイダ／モデル正規化

- provider 名は内部表現に正規化される
- model 名が欠落または不正な場合：
  - 補正可能であれば補正する
  - 補正不能な場合はエラーとして扱う

---

## LLM 呼び出し

### 入力要件

- 現在の文脈
- 今回のユーザー入力
- 有効な認証情報
- 必要に応じたシステムプロンプト設定

### 出力要件

- テキスト応答
- ツール起動要求（存在する場合）
- エラー情報（例外ではなく結果として）

---

## ツール起動（Tool Call）

### 位置づけ

- ツール起動は LLM 出力に基づく副処理である
- チャットループの一部として制御されるが、独立した責務を持つ

### ガード条件

- 無限ループを防止する上限を持つこと
- 許可されていないツールは起動しないこと
- ツール失敗時：
  - ログに記録する
  - チャット全体を失敗させない

---

## 出力整形・確定

- LLM 出力およびツール結果を統合する
- redact 等の安全処理を適用する
- UI 層へ返却する最終テキストを確定する

---

## 文脈への反映

- ユーザー入力および最終出力のみを文脈に追加する
- 途中失敗時は文脈を更新しない
- 要約操作は別仕様に従う

---

## Continuation（継続応答）

### 概念

Continuation とは、1 回の応答で完結しない場合に  
追加で LLM 呼び出しを行う制御である。

### 開始条件（例）

- 出力トークン上限に達した場合
- 明示的な継続要求がある場合

### 終了条件

- 完全な応答が得られた場合
- 最大継続回数に達した場合
- エラーが発生した場合

### 失敗時の扱い

- 途中結果が存在する場合はそれを返す
- 例外で停止してはならない

---

## Message 構造（概念）

- role（system / user / assistant / tool）
- content（文字列または構造化データ）
- 付随情報（timestamp 等、任意）

Message は **文脈の最小単位**であり、  
UI 表示構造と一致する必要はない。

---

## TextSplit（テキスト分割）

### 目的

- 長文を LLM 制限内に収める
- 意味的分断を最小化する

### 要件

- 文・段落単位を優先する
- 分割後も順序が保持される
- 分割不能な場合は安全側に倒す

---

## エラーおよび例外ポリシー

- チャットループは UI 層を例外で停止させない
- 例外はログに記録する
- UI には状態を識別可能な簡潔なエラーを返す
