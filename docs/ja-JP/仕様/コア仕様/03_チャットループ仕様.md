# チャットループ仕様

## Purpose（存在理由）

本書は、AIChaBo コアにおけるチャット実行処理の仕様を定義する。

本書は、入力受付から文脈処理、認証解決、LLM 呼び出し、ツール起動、出力確定、継続制御までの一連の流れを、実装から独立した宣言仕様として定義する。

---

## Non-goals（対象外）

本書は以下を対象外とする。

- 各 LLM プロバイダ固有 API の仕様
- Discord 等の UI 層における表示仕様
- 認証情報の保存方式および暗号化方式
- セッションおよび文脈の保持方式
- 利用者向け操作手順
- 実装方法、クラス構成、アルゴリズムの詳細
- テスト条件、テストケース、検証手順

---

## 基本概念

チャットループは、1 回のユーザー入力に対して実行される処理単位である。

チャットループは、入力、文脈、認証情報、LLM 呼び出し、ツール実行、出力反映を統合して処理する。

チャットループは、再入可能でなければならない。

チャットループは、途中失敗時でも安全に終了できなければならない。

チャットループは、UI 層を未処理例外で停止させてはならない。

---

## 全体フロー

チャットループは、以下の順序で処理される。

1. 入力検証
2. 文脈収集
3. 認証解決
4. プロバイダおよびモデル正規化
5. LLM 呼び出し
6. ツール起動
7. 出力整形および確定
8. 文脈反映
9. Continuation 判定

チャットループは、上記順序を破壊してはならない。

チャットループは、途中段階で失敗した場合でも、UI 層へ未処理例外を伝播させてはならない。

失敗時は、状態を識別可能な簡潔なエラー応答で終了する。

---

## 入力検証

チャットループは、入力が空でないことを確認する。

チャットループは、入力が想定外の型でないことを確認する。

チャットループは、最低限必要なメタ情報が存在することを確認する。

入力検証に失敗した場合、文脈は更新されない。

入力検証失敗は、内部的には例外として表現できる。

入力検証失敗は、UI 層では入力エラーとして扱われる。

---

## 文脈処理

チャットループは、対象スレッドに対応する文脈を取得する。

対象スレッドに対応する文脈が存在しない場合、空文脈として扱われる。

チャットループは、処理途中で文脈を直接永続化してはならない。

文脈反映は、出力確定後の段階で行われる。

---

## 認証解決と正規化

### 認証解決

認証解決は、各チャットループごとに実行される。

認証解決順序は、以下で固定する。

1. ユーザー設定
2. サーバー共有

認証情報が解決できない場合、LLM 呼び出しは実行されない。

### プロバイダおよびモデル正規化

provider 名は、内部表現へ正規化される。

model 名が欠落または不正である場合、補正可能な場合は補正される。

補正不能な model 名は、エラー状態として扱われる。

---

## LLM 呼び出し

LLM 呼び出しは、少なくとも以下を入力として扱う。

- 現在文脈
- ユーザー入力
- 有効な認証情報
- 必要に応じたシステムプロンプト

LLM 呼び出しは、少なくとも以下を結果として扱う。

- テキスト応答
- ツール起動要求
- エラー情報

LLM 呼び出し失敗は、未処理例外として UI 層へ伝播してはならない。

---

## ツール起動

ツール起動は、LLM 出力に基づいて行われる副処理である。

ツール起動は、チャットループの一部として制御される。

ツール起動は、独立した責務を持つ。

ツール起動は、無限ループを防止する制約を持たなければならない。

許可されていないツールは起動されてはならない。

ツール起動失敗はログへ記録される。

ツール起動失敗は、チャットループ全体の失敗を意味しない。

---

## 出力整形および確定

チャットループは、LLM 出力およびツール結果を統合する。

チャットループは、redact 等の安全処理を適用する。

チャットループは、UI 層へ返却する最終出力を確定する。

---

## 文脈反映

ユーザー入力は、対象スレッドの文脈へ反映される。

最終出力は、対象スレッドの文脈へ反映される。

途中失敗した処理結果は、文脈へ反映されてはならない。

要約操作は、スレッド・セッション仕様に従う。

---

## Continuation

Continuation は、1 回の応答で完結しない場合に、追加の LLM 呼び出しを行う制御である。

Continuation は、出力トークン上限到達または明示的継続要求等を契機として開始される。

Continuation は、完全な応答が得られた場合に終了する。

Continuation は、最大継続回数到達時に終了する。

Continuation は、エラー発生時に終了する。

Continuation が途中失敗した場合、途中結果が存在する場合は途中結果を返却できる。

Continuation は、未処理例外で停止してはならない。

---

## Message 構造

Message は、チャット文脈を構成する最小単位である。

Message は、少なくとも以下の情報を持つ。

- role
- content
- 任意の付随情報

role は、少なくとも以下の値を表現できる。

- system
- user
- assistant
- tool

content は、文字列または構造化データを表現できる。

Message 構造は、UI 表示構造と一致する必要はない。

---

## TextSplit

TextSplit は、長文を LLM 制限内へ収めるための分割処理である。

TextSplit は、意味的分断を最小化しなければならない。

TextSplit は、文単位または段落単位を優先する。

TextSplit 後も、入力順序は保持されなければならない。

安全な分割が不可能な場合、TextSplit は安全側の結果を返す。

---

## エラーおよび例外ポリシー

チャットループは、UI 層を未処理例外で停止させてはならない。

例外の詳細はログへ記録される。

UI 層には、状態を識別可能な簡潔なエラーが返却される。

復旧可能な不整合によって、チャットループ全体を停止させてはならない。
