# Web取得・添付・ユーティリティ仕様

## Purpose（存在理由）

本書は、AIChaBo コアにおける Web取得、添付管理、共通ユーティリティの仕様を定義する。

本書は、チャットループから利用される補助機能群について、責務、入出力、失敗時挙動、安全条件を定義する。

---

## Non-goals（対象外）

本書は以下を対象外とする。

- 各 LLM プロバイダ固有 API の仕様
- 認証情報の保存方式および暗号化方式
- セッションおよび文脈の保持方式
- チャットフロー全体
- 利用者向け操作手順
- 実装方法、クラス構成、アルゴリズムの詳細
- テスト条件、テストケース、検証手順

---

## 基本原則

すべてのユーティリティは、安全失敗を前提とする。

ユーティリティは、未処理例外によって UI 層またはチャットループを停止させてはならない。

ユーティリティは、同一入力に対して決定的な結果を返さなければならない。

ユーティリティは、単一責務に限定される。

ユーティリティの失敗はログへ記録される。

機密情報は、ログまたは返却値へ露出されてはならない。

---

## Web取得

### 目的

Web取得は、LLM 応答を補助するために、Web 上の情報を取得および整形する機能である。

Web取得は、チャットループに対する補助機能として扱われる。

### 構成

Web取得は、少なくとも以下の構成を持つ。

- 検索
- 読み取り

検索は、query を入力として URL 群を取得する。

読み取りは、URL を入力として本文抽出および整形を行う。

### 入力

Web取得は、少なくとも以下を入力として扱う。

- query
- URL
- 任意の取得オプション

### 出力

Web取得は、少なくとも以下を結果として扱う。

- 本文
- 要約テキスト
- 参照 URL

取得失敗時は、安全側の空結果を返す。

### 失敗時挙動

タイムアウト、HTTP エラー、本文抽出失敗等は、未処理例外として伝播してはならない。

取得失敗はログへ記録される。

取得失敗時は、空結果が返される。

取得不能な URL が存在する場合、当該 URL のみが失敗として扱われる。

一部 URL の失敗によって、Web取得全体を停止させてはならない。

### ガード条件

Web取得は、無限取得を防止する制約を持たなければならない。

Web取得は、必要に応じて危険 URL を拒否できなければならない。

同一 URL の重複取得は、正規化によって防止される。

---

## 添付管理

### 目的

添付管理は、UI 層から渡される画像またはファイル等の添付情報を安全に扱う機能である。

### 責務

添付管理は、少なくとも以下の責務を持つ。

- 添付メタ情報の正規化
- 添付 ID 単位での状態管理
- チャットループへの受け渡し

### 入力および出力

添付管理は、添付メタ情報を入力として扱う。

添付メタ情報は、少なくとも以下を表現できる。

- id
- type
- url または path

添付管理は、正規化済み添付情報を返す。

添付が存在しない場合、空状態が返される。

### 失敗時挙動

不正または欠落した添付メタ情報は、未処理例外として伝播してはならない。

不正または欠落した添付メタ情報は、当該添付のみを無効として扱う。

一部添付の失敗によって、他添付の処理を停止させてはならない。

### セキュリティ要件

添付内容はログへ出力されてはならない。

URL は必要最小限のみ保持される。

---

## JSONC 読み取り

### 目的

JSONC 読み取りは、コメント付き JSON を安全に解釈する機能である。

### 挙動要件

JSONC 読み取りは、コメントを除去した上で JSON として解釈する。

不正構文は、未処理例外として伝播してはならない。

不正構文時は、安全側の空 dict が返される。

### 決定性

JSONC 読み取りは、同一入力に対して同一出力を返さなければならない。

---

## ロギング

### 目的

ロギングは、障害解析および運用可視化を目的とする。

### 原則

ロギングは、機密情報を含んではならない。

例外スタックは、内部ログにのみ記録される。

ログ内容は、UI 出力またはチャット出力へ混入してはならない。

---

## redact

### 目的

redact は、API キー等の秘匿情報をログおよび出力から除去する機能である。

### 適用範囲

redact は、少なくとも以下へ適用可能でなければならない。

- ログ出力
- 例外メッセージ
- 必要最小限のチャット出力

### 要件

redact は、秘匿情報のマスキング漏れを許容してはならない。

redact は、過剰マスキングによって必要情報を破壊してはならない。

---

## prefetch

### 目的

prefetch は、事前取得によって応答時間を短縮する補助機能である。

### 要件

prefetch の失敗は、本処理を停止させてはならない。

prefetch の結果は、キャッシュ的に利用できる。

prefetch は、キャッシュの存在を前提としない。

---

## thread_utils

### 目的

thread_utils は、スレッド ID およびスレッド状態に関する補助処理を提供する。

### 挙動要件

不正または欠落した thread_id は、未処理例外として伝播してはならない。

thread_utils は、呼び出し側が判断可能な結果を返す。

削除済みまたは無効なスレッド状態を検出可能でなければならない。

---

## エラーおよび例外ポリシー

すべてのユーティリティは、UI 層またはチャットループを未処理例外で停止させてはならない。

例外の詳細は、内部ログへ記録される。

ユーティリティは、少なくとも以下の安全側結果を返却できなければならない。

- None
- 空配列
- 空 dict
- False
