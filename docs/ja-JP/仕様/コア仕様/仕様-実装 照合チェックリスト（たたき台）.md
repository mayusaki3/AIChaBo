# 仕様-実装 照合チェックリスト（たたき台）

本書は、コア仕様を実装（旧コード/AI生成コード）と突合するためのチェックリストである。

---

## A. 認証情報（テンプレ/解決順）
- [ ] 認証情報の解決順が「ユーザー＞サーバー共有」になっている
- [ ] /ac_auth で投入した情報はファイルとして保存されず、内容のみ保持される
- [ ] chat/vision/imagegen を独立して設定できる
- [ ] provider/model 欠落時の扱いが仕様どおり（エラー文言含む）

## B. 秘密ストア（暗号化/自己修復）
- [ ] 暗号化（Fernet）で保存されている
- [ ] JSON破損時に空辞書で復旧し、運用停止しない
- [ ] `providers` 等が dict でない場合に自己修復する
- [ ] delete 系が例外を投げず False を返す
- [ ] “鍵が存在するか”の判定が「復号できるか」になっている
- [ ] 並列 put の LWW 仕様が実装と一致している

## C. セッション/スレッド文脈
- [ ] スレッド単位で文脈キューが管理されている
- [ ] /ac_newtopic で文脈がクリアされる
- [ ] /ac_summary が要約→文脈クリアになっている（要約の保存方針も一致）
- [ ] Bot再起動後もスレッド管理が復元できる（永続化の粒度が仕様一致）
- [ ] 削除済みスレッドIDは自動で除去される（タイミング/方式）

## D. チャットループ
- [ ] 入力検証→文脈→認証解決→provider→ツール→出力→文脈反映の順序が概ね一致
- [ ] 継続（Continuation）の開始/終了条件が仕様どおり
- [ ] 例外時に簡潔エラー（詳細はログ）になっている
- [ ] ツール起動ガードがあり、無限ループしない

## E. Web取得/添付/ユーティリティ
- [ ] Web検索/読み取りの入力・出力フォーマットが仕様どおり
- [ ] URL正規化や失敗時の扱い（タイムアウト等）が仕様どおり
- [ ] 添付管理（attachment_id 等）の扱いが仕様どおり
- [ ] redact/logger/jsonc/file_io の“契約”が守られている
