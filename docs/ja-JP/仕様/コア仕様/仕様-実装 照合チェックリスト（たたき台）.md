# 仕様-実装 照合チェックリスト

## Purpose（存在理由）

本書は、AIChaBo コア仕様と実装（旧コードおよび AI 生成コード）を  
**体系的かつ再現性をもって照合するための基準仕様**を定義する。

本書は作業手順書や単なる TODO リストではなく、  
「**仕様に照らしたとき、実装が満たすべき確認観点**」を宣言的に示すものである。

---

## Non-goals（対象外）

本書は以下を目的としない。

- 実装修正手順や作業フローの記述
- テストケース詳細や自動テスト仕様の定義
- 実装差分の評価結果そのものの記録
- UI 操作やコマンド利用方法の説明

---

## 照合の前提

- 照合の正は **仕様ドキュメント** とする  
  （README・既存テスト・現行挙動は参考情報に留める）
- 実装は「仕様不足」「実装不具合」「仕様変更要否」のいずれかに分類される
- 本書は **実装世代（旧／AI 生成）に依存しない**

---

## A. 認証情報仕様との照合

- 認証情報の解決順が「ユーザー設定 ＞ サーバー共有」で固定されている
- 認証テンプレート投入時、ファイルそのものは保存されず内容のみ保持される
- chat / vision / imagegen が独立して設定可能である
- provider / model 欠落時の扱いが仕様と一致している

---

## B. 秘密ストア仕様との照合

- 機密情報が暗号化されて永続化されている
- JSON 破損時に空状態へ復旧し、運用が停止しない
- providers 等のノードが dict でない場合に自己修復される
- delete 系操作が例外を投げず False を返す
- 鍵存在判定が「復号可能か」を基準としている
- 並列 put において LWW が決定的に適用されている

---

## C. スレッド・セッション仕様との照合

- 文脈がスレッド単位でのみ管理されている
- /ac_newtopic により文脈が完全に破棄される
- /ac_summary により文脈が要約・軽量化される
- Bot 再起動後にスレッド管理が復元される
- 削除済みスレッド ID が自動的に除去される

---

## D. チャットループ仕様との照合

- 入力検証 → 文脈取得 → 認証解決 → LLM 呼び出し → ツール → 出力 → 文脈反映  
  の処理順が仕様と概ね一致している
- Continuation の開始条件・終了条件が仕様と一致している
- 例外発生時、UI 層には簡潔なエラーのみが返却されている
- ツール起動に無限ループ防止のガードが存在する

---

## E. Web取得・添付・ユーティリティ仕様との照合

- Web 検索／読み取りの入出力形式が仕様どおりである
- URL 正規化および取得失敗時の扱いが仕様どおりである
- 添付管理が attachment_id 単位で行われている
- redact / logger / jsonc / file_io 等の契約が一貫して守られている

---

## 照合結果の扱い（指針）

照合の結果得られた差分は、以下のいずれかに分類される。

- **仕様不足**：仕様を更新すべき事項
- **実装不具合**：実装を修正すべき事項
- **仕様変更要否**：方針決定を要する事項

本書自体は、これらの判断結果を記録しない。
